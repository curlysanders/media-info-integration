Status: **complete — unavailable third-party `fb_extern` registration**. This is a version-scoped negative result for the disposable `DSM-7.4-Test` VM: DSM `7.4.1-90080 Update 1`, presented as DS1621+ on `v1000`, guest CPU `AMD Ryzen 5 5500U with Radeon Graphics @ kvm` (2 cores), and File Station `1.4.4-2221`. It does not make a claim about another DSM build, hardware platform, or a future Synology extension contract.

Each attempt used one selected regular `.mp4` file. A non-media text fixture had no experimental item, as expected. Existing File Station controls—including download, open in a new tab, properties, and sharing—remained present and functional after every package upgrade. No DSM or File Station file was patched, injected, decrypted, replaced, or redistributed. The package itself loaded its declared JavaScript resource in DSM, but that did not cause File Station `1.4.4-2221` to register the third-party action.

## Decision

The legacy `fb_extern` artifacts remain useful historical evidence, but on this exact DSM/File Station target they are **not an available integration surface**: a correctly launching DSM 7 third-party application and the current official Text Editor both have no File Station action. This completes P1-007 as unavailable and blocks Phase 3 only. It does not change P1-004's separate exact-file-authorization result, and it does not authorize a DSM patch, a browser injection, or a privilege-expanding helper as a workaround.

The probe and official Text Editor are deliberately left installed only on the disposable target for repeatability. Enable/disable and uninstall removal tests are not meaningful until DSM accepts a registration; they remain unperformed rather than inferred.
