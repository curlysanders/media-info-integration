# P1-002 evidence — 27 October 2026

Status: **in progress**. Target: local `DSM-7.4-Test` Arc Loader VM. This document records the implementation baseline and reserves live observations. It makes no claim that the package has been installed or that PHP or Go has passed on DSM.

On 27 October 2026, Package Center first rejected the locally packed SPK as an invalid file format. The outer archive was compressed and package icons were absent. The build now creates an uncompressed outer tar archive, required 64×64 and 256×256 PNG icons, and an MD5 for `package.tgz`, matching the published DSM package layout. Package Center then accepted the archive format but rejected its privilege declaration as root. The privilege metadata was reduced to the documented minimal `run-as: package` form; Package Center then installed the package and created the `mediainfo-poc` account (UID/GID 241653).

The initial lifecycle script started `runtime-probe` under that package account, but `synopkg status` reported the package stopped with status 263 and the expected nginx registration did not appear. The 404 at the probe route is therefore a routing/lifecycle failure, not a Go process or package-account failure. DSM rejected both 0.1.0-2 and 0.1.0-3 as an invalid package format when they declared `systemd-user-unit`, including the documented `pkguser-*` naming variants. Version `0.1.0-5` restores the byte-for-byte validated lifecycle layout from the initially accepted 0.1.0-1 package before further DSM-side diagnosis; retest is pending.
